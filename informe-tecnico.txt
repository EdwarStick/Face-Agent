# FLUJO REAL DEL SISTEMA

```
Usuario abre SPA (React en navegador)
?
Dashboard: ve resumen (empleados, rostros, marcaciones)
?
Gestion Empleados
  +-- Lista empleados + busqueda
  +-- Crear empleado (formulario)
  +-- Editar empleado
  +-- Ver detalle empleado
  +-- Desactivar empleado (soft delete)
    +-- Desde detalle: boton "Registrar Rostro"
        +-- Modal: camara ? capturar ? previsualizar ? confirmar
            +-- Backend: genera embedding DeepFace, guarda en DB
?
Reconocimiento Facial
  +-- Pagina: camara EN VIVO ? boton "Reconocer"
      +-- Backend: genera embedding, compara contra DB, umbral 0.70
          +-- Si reconoce: muestra nombre, cargo, confianza
          +-- Si no reconoce: "Sin coincidencia"
          +-- (NO hay opcion de marcar entrada/salida desde aqui)
?
Control de Asistencia
  +-- Pagina: filtros + summary + tabla paginada
      +-- (solo consulta -- no hay boton "Marcar entrada" desde UI)
      +-- Backend: API para registrar entrada/salida existe pero no hay UI para ello
?
(El usuario no puede marcar asistencia desde la interfaz web,
  aunque la API lo soporta)
```

**Importante:** No existe un flujo de "empleado llega, se para frente a camara, sistema lo reconoce Y registra entrada automaticamente". El reconocimiento y el marcaje son dos acciones separadas sin conexion en UI.

# SIGUIENTE FEATURE RECOMENDADA

**Integracion reconocimiento ? registro de asistencia**

**Justificacion tecnica:**
1. El sistema TIENE ambas capacidades pero operan desconectadas. El backend expone endpoints separados (`/reconocimiento/identificar` y `/asistencias/entrada`) que nunca se llaman en secuencia.
2. La UI de reconocimiento facial muestra el resultado pero no ofrece accion posterior.
3. Es el feature de menor esfuerzo (~1-2 dias) porque ambos lados ya existen:
   - Backend: crear endpoint `POST /reconocimiento/marcar-entrada` que haga identificar + registrar entrada en una transaccion
   - Frontend: agregar boton "Marcar Entrada" en el `RecognitionResultCard` cuando el reconocimiento es exitoso
4. **Valor inmediato:** Convierte el sistema de "demo tecnica" a "producto usable". Un empleado puede pararse frente a la camara, ser reconocido y marcar entrada en segundos.

# ROADMAP RESTANTE

Ordenado por prioridad para llegar a MVP producible:

1. **Integracion reconocimiento ? asistencia** (unir flujo completo)
2. **Autenticacion basica** (login con JWT, proteger rutas API y frontend)
3. **Crear migracion inicial Alembic real** (`empleados`, `rostros`, `asistencias`)
4. **UI para marcar entrada/salida** (boton "Marcar Entrada" despues de reconocimiento + boton "Marcar Salida")
5. **Tardanzas** (definir hora esperada de entrada por empleado/turno, calcular automaticamente)
6. **Dashboard con graficas** (Chart.js o recharts para tendencias diarias/semanales)
7. **Reportes basicos** (PDF/Excel exportable de asistencias por rango de fechas)
8. **Horas extra** (definir jornada base, calcular excedente)
9. **Carga masiva de empleados** (CSV/Excel)
10. **Tests para rostros, reconocimiento, asistencias** + base de datos de testing
11. **Notificaciones** (alertas de empleados sin marcar, tardanzas recurrentes)
12. **Azure AI / chat empresarial** (features de IA -- baja prioridad, no bloqueante)
